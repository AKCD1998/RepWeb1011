# บันทึกยอดคงเหลือรายลอตเมื่อจบรอบ ข.ย.10/11

สถานะ: งานต่อยอดหลังรอบรายงานกันยายน 2569 ยังไม่ได้สร้างระบบหรือยืนยันยอดย้อนหลัง

## ปัญหาที่พบ

เว็บเก็บ snapshot ไฟล์นำเข้า ข.ย.11 ช่วง 18 มิ.ย.–27 ก.ย. 2569 เพื่อสร้างซ้ำได้ แต่ snapshot นี้มีลอต/ความจุจำลองสำหรับพัฒนา 78 คู่สินค้า–สาขา และไม่ใช่รายงานยอดคงเหลือที่ตรวจนับแล้ว ร่างรายสินค้าที่เคยสร้างมีช่วงวันไม่เท่ากัน บางชุดเป็นเพียงบันทึกตรวจ POS ที่ยังไม่ผูกลอต การกลับมาทำรายงานงวดถัดไปจึงไม่มีตัวเลขยกมารายสินค้า–ลอต–สาขาที่อ้างอิงได้โดยตรง

## สิ่งที่ต้องเพิ่มหลังจบรอบปัจจุบัน

- ให้ผู้ดูแลระบบบันทึก **ยอดคงเหลือ ณ วันสิ้นงวด** แยกสาขา รหัสสินค้า เลขลอต และหน่วย พร้อมช่วงงวดและเวลา Asia/Bangkok
- แสดงวิธีคำนวณต่อแถว: ยอดยกมา + รับเข้า + โอนเข้า + คืนเข้าสต๊อก − ขาย − โอนออก − ปรับลด โดยเก็บการคืน/ยกเลิกเป็นรายการแยก ไม่หักยอดเงียบ ๆ
- เก็บที่มาเลขเอกสาร/รหัส movement, ไฟล์ต้นทางและ SHA-256, เวลาที่ดึงข้อมูล, จำนวน/หน่วยเดิม, อัตราแปลงหน่วย และสถานะยืนยันลอตจริงของสาขา
- แยกสถานะ `ร่าง`, `รอตรวจ`, `ยืนยันแล้ว`; ข้อมูลที่ขาดต้องแสดงว่าไม่ทราบ ไม่แทนด้วยศูนย์ และห้ามยกระดับลอตที่อนุมานหรือวันที่หัวเอกสารเป็นรับเข้าจริงโดยอัตโนมัติ
- เก็บ snapshot แต่ละงวดแบบมี version และแก้ย้อนหลังด้วย revision ใหม่ที่ตรวจสอบได้ ผู้ดูแลระบบค้นตามงวด/สาขา/สินค้าและดาวน์โหลดไฟล์ยอดคงเหลือได้
- ใช้ยอดสิ้นงวดที่ยืนยันแล้วเป็นยอดยกมาของงวดถัดไป โดยแสดงการเปลี่ยนแปลงหลังปิดงวดแยก ไม่แก้ข้อมูลอ้างอิงเดิมเงียบ ๆ
- จำกัดสิทธิ์ดูไฟล์และ API ไว้ภายในระบบ ไม่เผยข้อมูลผู้ซื้อในไฟล์สต๊อก และไม่เปลี่ยน algorithm จัดสรรผู้ซื้อ/การซื้อของตัวสร้างรายงานเดิม

## เกณฑ์ตรวจรับ

1. ปิดงวดตัวอย่างหนึ่งครั้งแล้วดาวน์โหลดไฟล์ที่มีครบทุกคู่สินค้า–ลอต–สาขา พร้อมยอดและหลักฐานที่มา
2. เปิดเว็บภายหลังแล้วยังเรียก snapshot เดิมด้วยวันสิ้นงวด/version เดิมได้ โดยผลและ checksum ตรงกัน
3. เริ่มงวดถัดไปแล้วระบบดึงเฉพาะยอดสิ้นงวดที่ยืนยันแล้วเป็นยอดยกมา; รายการที่ยังไม่ยืนยันคงสถานะรอตรวจ
4. การแก้รับเข้า/ขาย/โอนหลังปิดงวดสร้าง revision และ audit trail; ไม่เปลี่ยน snapshot เก่า
5. ตรวจตัวอย่างรายการคืน ยกเลิก หน่วยต่างกัน ลอตที่ไม่ทราบ และการโอนข้ามสาขา โดยไม่บวกซ้ำ

สำหรับรอบกันยายน 2569 ปัจจุบันยังไม่มีไฟล์คงเหลือ ณ 27 ก.ย. แยกรายลอตที่ยืนยันแล้ว ผลเทียบหลักฐานย้อนหลังในโฟลเดอร์ `R20_KY1011_SEPTEMBER_DRAFT_20261024` เป็นเพียงการคัดกรอง ไม่ใช่ยอดยกมา
