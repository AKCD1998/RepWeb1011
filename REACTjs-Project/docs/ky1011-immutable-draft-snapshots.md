# ตรึงข้อมูลร่าง ข.ย.11 รายการยาที่ อย. กำหนด เพื่อสร้างช่วงเดิมซ้ำ

สถานะ 27 ต.ค. 2569: เว็บเก็บ **ข้อมูลต้นทางถึง 24 ต.ค. แบบแก้ทับไม่ได้แล้ว แต่ยังไม่ได้เก็บผลร่างหลังประมวลผล** จุดเน้นของงานนี้คือ 27 รหัส dextromethorphan และยาแก้แพ้ชนิดน้ำใน **ข.ย.11 ตามรายการที่ อย. กำหนด** ส่วน **ข.ย.10 คือยาควบคุมพิเศษ** และเป็นรายงานอีกกลุ่มหนึ่ง เอกสารนี้บันทึกสิ่งที่ต้องเก็บและแยกจากข้อมูลที่เว็บเก็บอยู่แล้ว ห้ามถือว่าการมี PDF หรือไฟล์ยอดขายต้นทางเท่ากับการเก็บผลร่างหลังประมวลผล

## กติกาที่ผู้ใช้ยืนยัน

- ระบุรอบด้วยวันเริ่ม–วันสิ้นสุด (Asia/Bangkok), กลุ่มรายงาน (ข.ย.11 หรือ ข.ย.10 แยกกัน), สาขา, สินค้า และเลขเวอร์ชัน
- เมื่อร่างผ่านการตรวจแล้ว ให้เก็บข้อมูลต้นทางและ **ผลหลังประมวลผล** ของเวอร์ชันนั้น: รายการขาย/จ่าย, การรับเข้าและโอน, ลอตและยอดยกมา, หน่วยและอัตราแปลง, การจัดสรรยอดซื้อ/ลอต, ชื่อผู้ซื้อที่ถูกเลือก, ลำดับและข้อความแต่ละแถว, เวอร์ชันตัวสร้างรายงานและแม่แบบ, PDF ที่ตรวจแล้ว พร้อม SHA-256 และสถานะหลักฐาน
- การเปิดหรือดาวน์โหลดช่วงและเวอร์ชันเดิมต้องได้ร่างเดิมทุกแถวและ PDF เดิม การแก้ข้อมูลภายหลังสร้าง revision ใหม่ มีเหตุผล ผู้แก้ เวลา และความต่างจากเวอร์ชันก่อน เก็บฉบับเดิมไว้
- ข้อมูลที่ยังไม่ยืนยัน เช่น ลอต/ความจุจำลอง วันที่หัวกระดาษแทนวันรับจริง หรือยอดคงเหลือที่ไม่ทราบ ต้องคงสถานะร่าง/รอตรวจ ห้ามยกระดับเป็นข้อมูลยืนยันอัตโนมัติ
- เก็บชุดข้อมูลที่มีชื่อผู้ซื้อและเลขบัตรใน backend ที่จำกัดสิทธิ์ ไม่ใส่ข้อมูลนั้นใน frontend สาธารณะหรือไฟล์รายงานยอดคงเหลือ และไม่เปลี่ยน algorithm จัดสรรเดิมเพียงเพื่อให้ผลสร้างซ้ำ

## เกณฑ์ตรวจรับของระบบที่จะเพิ่ม

1. ผู้ดูแลระบบบันทึกร่างพร้อมไฟล์ต้นทาง, normalized inputs, ผลจัดสรร, PDF, checksum, สถานะตรวจ และตัวระบุเวอร์ชันใน transaction ที่ตรวจสอบย้อนหลังได้
2. กลับมาเปิดรอบ/เวอร์ชันเดิมภายหลังแล้วได้แถวและ PDF ตรง checksum เดิม แม้ข้อมูลสดหรือรายชื่อผู้ป่วยเปลี่ยนไป
3. เพิ่มหรือแก้หลักฐานแล้วสร้าง revision ใหม่ ฉบับเดิมยังดาวน์โหลดได้และเห็นเหตุผลการเปลี่ยน
4. ทดสอบทั้ง ข.ย.10 และ ข.ย.11, หลายสาขา, หลายลอต, การคืน/ยกเลิก, หน่วยต่างกัน, ลอตที่ยังไม่ยืนยัน และรอบที่ข้ามเดือน
5. ผู้ใช้ทั่วไปเข้าถึง snapshot ที่มีข้อมูลผู้ซื้อไม่ได้; การเรียกดู/ดาวน์โหลดมี audit log

ยังไม่มีการ migrate หรือบันทึก **ผลร่างหลังประมวลผล** ลงฐาน production จากเอกสารนี้ การบันทึกที่ทำแล้วคือ CSV ต้นทางเท่านั้น
