# Bulk ขย.11 จากประวัติขาย

หน้า `#/reports` → ส่วน Dextromethorphan/1st Generation Antihistamine → **Bulk ขย.11 · หลายสินค้า / สาขา**

1. อัปโหลดหลาย CSV พร้อมกัน หรือ CSV รวมสินค้าและสาขา รองรับ JSON `rows` รูปแบบ `POS_LOT_ASSIGNMENTS_LOT_INFERENCE_20260929_V2.json` ด้วย
2. ไฟล์รวมใช้ `branchCode,productCode,saleDate,quantity,billNo,unit` รองรับหัวคอลัมน์ไทยและ StockDay (`ic_code`, `sale_date`, `quantity`, `bill_no`)
3. CSV เดิมที่มีเพียงวันที่และจำนวน ให้เลือกสินค้า/สาขาในรายละเอียดแต่ละไฟล์ หากเป็นไฟล์ที่เพิ่มแถวแรกซ้ำเพื่อใช้กับตัวตรวจคอลัมน์เดิม ให้เลือก **ข้ามแถวข้อมูลแรก** โดยชัดแจ้ง
4. อัปโหลดลอตแยกตามสาขา: `branchCode,productCode,batch,received_date,boxes,units_per_box` หรือกรอก/แก้ลอตในแต่ละงาน กด **แม่แบบลอตตามงานที่นำเข้า** เพื่อดาวน์โหลดรายการงานทั้งหมดพร้อมช่องที่ต้องเติม
5. เลือกช่วงวันที่และงาน ตรวจยอด/หน่วย/ลอต แล้วเลือกช่องยืนยันก่อน **สร้าง ขย.11 ทั้งชุด**
6. ดูความคืบหน้า หยุดระหว่างงาน สร้างงานที่เหลือต่อ หรือลองใหม่เฉพาะงานล้มเหลวได้ งานที่สำเร็จคงชื่อผู้ซื้อเดิมเมื่อทำต่อ/ลองใหม่
7. เลือกดูตัวอย่างงานเดียวหรือทั้งหมด พิมพ์/บันทึก PDF รวมทุกงานที่สำเร็จ หรือดาวน์โหลด CSV รวม

รองรับสาขา 001, 003, 004, 005 โดยคงตัวเลือกของโหมดทีละสินค้าเดิมไว้ ไม่มีการเขียนยอดขาย ลอต หรือการจ่ายกลับฐานข้อมูล ไม่มีการบันทึกข้อมูลนำเข้าและผลรายงานลง localStorage และไม่มีการ commit/push/deploy อัตโนมัติ

## ขอบเขตการตรวจข้อมูล

- จับคู่รหัสสินค้า/ID ก่อนชื่อ; ชื่อซ้ำหลายขนาดบรรจุต้องใช้รหัสที่แน่นอน ใช้รายการ KY11 จาก catalog ของแอป ไม่แปลง KY10 เป็น KY11
- จำนวนขายต้องเป็นจำนวนเต็มบวกในหน่วยเดียวกับรายงานเดิม ไม่มีการเดา conversion จากข้อความหน่วย POS รายการคืน/เศษหน่วยต้องตรวจแยก
- ตรวจวันตามปฏิทิน รองรับ พ.ศ. และ ค.ศ. ช่วงวันที่รวมวันเริ่ม/สิ้นสุด
- เก็บเวลาไทยจากประวัติขายไว้ และส่ง HH:mm:ss ให้ algorithm เดิมด้วย ไม่บวกเวลาเพิ่มหรือเปลี่ยนข้อมูลเป็นเวลาเที่ยงคืน
- บิลซ้ำ SKU/สาขา/เลขบิลที่ข้อมูลเหมือนกันรวมเพียงครั้งเดียว บิลเดียวที่ยอดหรือวันต่างกันเป็นข้อผิดพลาด หาก export มีหลายบรรทัด SKU เดียวต่อบิล ต้องรวมเป็นยอดต่อ SKU/บิลก่อนนำเข้า ไม่รวมแถวที่ไม่มีเลขบิลเพียงเพราะวันและจำนวนเหมือนกัน
- ข้อผิดพลาดการอ่าน/นำเข้าและลอตไม่พอจะหยุดการเริ่มชุด หาก builder ล้มเหลวเฉพาะงาน งานอื่นยังทำต่อได้
- `buildBulkReportItem` เรียก `buildReport` เดิมโดยไม่แก้ `buildReport.js`, `csv.js` หรือ algorithm การเลือกผู้ซื้อ ตัว adapter เพิ่มแถวตรวจคอลัมน์ที่ builder เดิมข้าม แล้วส่งยอดจริงทั้งหมด รวมทั้งแบ่ง input เกิน 500 หน่วยให้ตรงขีดจำกัดตัวตรวจเดิม
- ตรวจยอด output เท่ากับยอด input พร้อมตรวจยอดเกินกล่องและยอดขายก่อนวันรับลอต หากพบข้อจำกัดการจัดสรรเดิมจะแสดงข้อผิดพลาด ไม่แก้ logic เดิมเอง
- จำกัดไฟล์ 20 MB และจำนวนรับ/ยอดขาย 100,000 หน่วยต่อหนึ่งงาน
- การเปลี่ยนข้อมูลนำเข้า ช่วงวันที่ งานที่เลือก หรือลอต จะล้างผลเก่าและต้องตรวจยืนยันใหม่

## ชุดข้อมูลอ้างอิงของผู้ใช้

สคริปต์ `scripts/prepare-manual-bulk-inputs.mjs` อ่าน lot register และ POS JSON ที่ผู้ใช้ให้ กรองตาม KY11 ใน source register พร้อมรวม CSV Iyafin ชุดแรก แล้วสร้าง CSV สำหรับนำเข้าโดยไม่มีชื่อ/เลขบัตรผู้ป่วย เก็บรายการ nonpositive ในไฟล์ audit แยก และสร้างแม่แบบลอตที่ **เว้นจำนวนรับของแต่ละสาขาไว้** เพราะจำนวนบนใบกำกับสำนักงานใหญ่ไม่ใช่หลักฐานจำนวนรับของทุกสาขา

```text
node scripts/prepare-manual-bulk-inputs.mjs --source-dir <All_Branches_PDF> --out-dir <new sibling development folder>
```

ใช้ข้อมูลและผลร่างนี้เพื่อพัฒนาระบบตามคำขอของผู้ใช้ สคริปต์ไม่แก้ไฟล์ต้นทางและไม่เขียนทับ output ที่มีอยู่

## Validation

`npm run test:backend -- --runTestsByPath tests/frontend/manual-bulk-report.test.mjs` ครอบคลุมการแยกงาน, KY11 eligibility, ข้อมูลไม่ครบ, บิลซ้ำ, ปี พ.ศ., legacy padding, POS original quantities, สาขา 005, หน่วย/ลอตไม่พอ, ยอดเกินกล่อง, วันรับลอต และ CSV รวม

`npm run ci` ตรวจ syntax backend และ build production frontend; ตรวจ browser เพิ่มด้วย API fixtures และผู้ซื้อสังเคราะห์ใน localhost

ตรวจเมื่อ 29/09/2026: tests รวม 70 ข้อผ่าน; browser นำเข้าชุดอ้างอิง 1,532 แถว / 11 สินค้า / 4 สาขา แล้วสร้างครบ 42 งาน ยอดรวม 2,102 หน่วยตรงกับ input โดยใช้ลอตและผู้ซื้อสังเคราะห์สำหรับ QA เท่านั้น ตรวจการยกเลิกและสร้างต่อโดยผลของงานที่สำเร็จไม่เปลี่ยน ตรวจหน้าจอ 390 px และ PDF รวมชุดเล็ก 3 หน้าจาก 3 งาน โดย render และดูครบทุกหน้าแล้ว
